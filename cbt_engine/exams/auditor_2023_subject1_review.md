## 2. 해설 보강 표준 포맷 체계

```markdown
정답: ①/②/③/④

[출처]
대분류 > 중분류 > 세부 토픽명

[해설]
1) 문제 출제 배경 및 핵심 평가 요소
2) 정답 도출 원리 및 핵심 근거 법령/이론 조문
3) 각 지문별(①~④) 상세 정오답 판정 및 해설

💡 [실무 쟁점 & 핵심 Q&A 노트]
• 실무적 쟁점, 직관적 비유(아파트 건설 비유 등)
• 출제위원의 단어 함정 판별 공식
• 연계 심화 공식 및 시험용 1초 암기 팁
```

## 3. 문항별 핵심 보강 내역 및 학습 인사이트

| 문항 | 핵심 토픽 | 정답 | 주요 보강 내용 및 핵심 인사이트 |
| :---: | :--- | :---: | :--- |
| **Q1** | EVM 진척 산정 (고정비율법) | **①** | • 20/80 룰 기반 고정비율법(Fixed Formula)<br>• 물리적 실측치 왜곡 방지를 위한 '사전 약정 룰' 개념 정립 |
| **Q2** | 개발 생애주기 (반복형) | **②** | • $Agile = Iterative + Incremental$ 공식<br>• 모나리자/건설 비유: 전체 조감도/골조부터 다듬는 반복형 vs 101동 먼저 입주시키는 점증형 |
| **Q3** | 일정 네트워크 기법 (GERT) | **①** | • GERT 3대 특징: 확률적 분기, 피드백 루프(재작업), 임의의 모든 확률분포(베타분포 고정은 PERT)<br>• 현실 리스크 반영 순서: $CPM < PERT < GERT$ |
| **Q4** | WBS 작업 패키지 관리 | **②** | • 8/80 룰 및 보고주기 룰 (90% 증후군 방지)<br>• WBS 최하위는 작업 패키지(명사/인도물), 일정표 최하위는 Activity(동사/행동)<br>• 보고주기 연장이 아닌 작업패키지 분할(Decomposition) 원칙 |
| **Q5** | 프로젝트 범위 분할 개념 | **①** | • 가치흐름맵(VSM)은 린(Lean) 프로세스의 낭비(Waste) 제거 도구<br>• 애자일 계층(테마➔에픽➔피처➔사용자스토리) 비교 |
| **Q6** | EVM 4대 성과 지표 계산 | **③** | • $CV=10, SV=20, CPI=1.1, SPI=1.22 \ne 0.9$<br>• 모든 공식은 EV로 시작 원칙 및 $EAC = BAC / CPI$, $EAC = AC + (BAC - EV)$ 정리 |
| **Q7** | 일정 단축 기법 (중첩 vs 압축) | **②** | • Fast Tracking(병렬 수행, 재작업 리스크 급증) vs Crashing(자원/비용 추가 투입)<br>• 101동 동시 착수 vs 101동 야간작업 인력 2배 투입 비유 |
| **Q8** | PMBOK 7판 8대 성과 영역 | **②** | • 12대 원칙(마음가짐/철학 - 가치, 리더십 등) vs 8대 성과영역(집중 대상 - 팀, 인도, 측정 등)<br>• '가치(Value)'는 최상위 나침반(원칙)이며 인도/측정 영역에서 실현·검증 |
| **Q9** | 터크만 팀 발달 (규범기) | **④** | • 5단계 리더십 매칭: 형성기(지시) ➔ 폭풍기(코칭) ➔ 규범기(지원/일체감) ➔ 성과기(위임) ➔ 해산기(축하)<br>• R&R 정의는 형성기/폭풍기 역할 |
| **Q10** | 조직의 팀 유형 (교차기능팀) | **②** | • 교차기능팀(TFT/애자일 스쿼드)은 다기능 융합으로 비즈니스 목표·속도·비용을 종합 추구<br>• 품질/가치만 중시하는 것은 문제해결팀(분임조) 특성 |
| **Q11** | 골만 감성지능(EI) 4대 영역 | **①** | • [나 vs 남] × [인식 vs 관리] 2×2 매트릭스<br>• '자기판단'이라는 영역 없음 (비판/평가가 아닌 알아차림인 '자기인식'이 핵심) |
| **Q12** | 다니엘 핑크 동기부여 (AMP) | **④** | • AMP = Autonomy(자율성), Mastery(숙련도), Purpose(목적)<br>• '성취(Achievement)'는 맥클리랜드 획득욕구이론 항목 |
| **Q13** | 감리수행 가이드 점검항목 | **③** | • '기술적용계획표' ➔ 요구정의단계 vs '기술적용결과표 준수 여부' ➔ 종료단계 감리 |
| **Q14** | 감리기준 업무 절차 및 R&R | **③** | • 과업대비표 작성 주체: 사업자 작성 ➔ 발주자 확인 ➔ 감리법인 제출<br>• 감리법인 3대 문서(계획서, 결과보고서, 시정조치확인보고서)는 발주자/사업자 모두 통보 |
| **Q15** | SW진흥법 적정 사업기간 산정제 | **④** | • 1년 초과 시 장기계속계약 체결 의무 (유지관리 제외, 기관장 산정 1억 이하)<br>• 1인 생산성 +3 규칙: 16 ➔ 19 ➔ 22 ➔ 25 ➔ 28 FP/MM |
| **Q16** | SW 대가산정 가이드 유형별 방식 | **④** | • 개발/재개발 ➔ 기능점수(FP), 유지관리 ➔ 요율제(%), 기획/ISP ➔ 컨설팅(M/M)<br>• 투입공수(헤드카운팅) 방식 원칙적 금지 |
| **Q17** | SW 영향평가 제외 사업 | **④** | • 민간투자형, 단일기관 내부용, DB구축 모두 제외 (민간 상용SW 시장 침해 우려 없음)<br>• 민간투자형 SW사업의 법적 자격(과기정통부 적격성 승인 및 민간 자본 투자) |
| **Q18** | 전자정부법 의무감리 대상 사례 | **①** | • '중앙행정기관등'에 지자체 및 공기업/공사/공단 포함 (공동 사용 해당)<br>• 의무감리 4대 요건 및 순수 개발비 1억 미만 시 감리 생략 기준 |
| **Q19** | 감리법인 행정처분 기준 | **①** | • 1차 처분 수위: 거짓 보고서(경고) < 거짓 변경신고(1개월) < 명의대여/무자격자(6개월) < 부정등록(등록취소)<br>• 서류/보고서 오류는 1차 '경고'로 시작 |
| **Q20** | 감리기준 상주감리 및 편성 | **①** | • 상주감리원의 단계별 감리 참여 절대 금지 (독립성/셀프 감리 방지)<br>• 20억 미만 2단계 감리, 타분야 전문가 30% 이내 |
| **Q21** | ISP/ISMP 사전검토 3대 분야 | **③** | • 3대 검토 분야 [타·실·규]: 사업 타당성, 실현 가능성, 규모 적정성<br>• 거시적 경제성(B/C)은 KDI 예타에서 검증 |
| **Q22** | 공공데이터 개방 기본원칙 | **②** | • 공공데이터의 '영리적 이용 제한 절대 금지' (2013년 서울버스 앱 사태 배경)<br>• 카카오맵, 호갱노노 등 민간 비즈니스 창출 보장 |
| **Q23** | 상용SW 직접구매 (분리발주) | **②** | • 직접구매 = 분리발주<br>• 다량 구매로 5천 초과 시 5천 이상 간주(쪼개기 방지)<br>• 민간투자형 SW사업은 직접구매 제외 가능, 하도급 승인 10일 간주제 |
| **Q24** | SW 영향평가 절차 및 공시 | **④** | • 결과서는 비공개 제출이 아니라 홈페이지 등에 '대외 공시(공개)' 의무<br>• 주무부처는 과학기술정보통신부<br>• 자체개발(국가소유/무상확산➔침해우려➔영향평가) vs 상용SW(라이선스 구매➔각각 구매➔영향평가 제외) |
| **Q25** | 정보시스템 구축·운영 지침 | **②** | • 개인정보 영향평가(PIA)는 정보시스템 【설계완료 전】에 수행 (분석완료 전 ❌)<br>• 분석(What 파악) ➔ 영향평가 ➔ 설계(How 암호화/마스킹 반영) 타임라인 |
