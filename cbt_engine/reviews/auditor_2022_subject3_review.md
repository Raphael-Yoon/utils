### 📌 [Q01 (전체 51번)] 데이터베이스 3단계 설계 라이프사이클 (논리적 설계 vs 물리적 설계 R&R)

**📋 문제 본문 및 보기:**
```text
데이터베이스 설계 단계 중 논리적 설계 단계에서 수행하는 작업으로 가장 적절하지 않은 것은?

① 개념적 설계 단계에서 생성된 ER 다이어그램을 관계형 데이터 모델의 릴레이션으로 변환한다.
② 릴레이션의 정규화 과정을 수행하여 데이터 중복 및 갱신 이상을 최소화한다.
③ 트랜잭션의 인터페이스 및 상세 처리 절차를 설계한다.
④ 성능 향상을 위해 인덱스 구조, 테이블 저장 공간, 클러스터링 등을 물리적으로 배치한다.
```

**🎯 정답:** ④번

#### 💬 실시간 1:1 심층 대화 전문 (Full Dialogue)
* **🧑‍💻 [매니저님]**: "ERD를 그리는 단계가 개념설(개념적) 설계 단계?"
* **🎓 [임선우 코치]**: "네, 매니저님! 데이터베이스 공학 학술 표준(Silberschatz / Elmasri)에서 **ER 다이어그램(ERD)을 설계하고 그리는 단계는 명백히 '개념적 설계(Conceptual Design)' 단계**입니다. 특정 DBMS와 무관하게 비즈니스 요구사항을 추상화하여 개념적 ERD를 완성합니다. 그리고 논리적 설계 단계에서는 이 ERD를 목표 관계형 데이터 모델의 릴레이션(테이블) 스키마로 사상(Mapping)하고 정규화를 수행합니다."
* **🧑‍💻 [매니저님]**: "굳이 나눠보자면 개념적 설계 단계에서는 큰 도면에 ER모델링을 그리고, 논리적 설계 단계에서 ERWin같은 도구로 실제 스키마를 작성하고, 물리적 설계 단계에서 테이블을 생성하는건가?"
* **🎓 [임선우 코치]**: "매니저님의 실무 매핑이 본질을 매우 정확하게 짚으셨습니다! 다만 시험에서 자주 파는 함정이 있습니다:
  1. 개념적 설계: 화이트보드/도면에 비즈니스 핵심 개체와 관계를 큰 그림으로 스케치 (개념적 ERD)
  2. 논리적 설계: ERwin 등에서 릴레이션 변환, 정규화(1~3NF), FK/무결성 정의 (논리 스키마)
  3. 물리적 설계: 타깃 DBMS 환경에 맞춰 인덱스, 파티셔닝, 반정규화, 스토리지 용량 산정 및 DDL 스크립트 도출
  4. 구현 단계: **실제 DBMS 콘솔에서 CREATE TABLE DDL을 실행하여 테이블을 생성하고 데이터를 적재하는 행위는 '구현(Implementation) 단계'**입니다.
  따라서 '물리적 설계 = 테이블 생성'으로 지문이 나오면 오답이 될 수 있음을 주의해야 합니다."
* **🧑‍💻 [매니저님]**: "아.. 또 구현 단계가 있구나. 그리고 정규화 과정은 논리적 설계 단계고.."
* **🎓 [임선우 코치]**: "네, 정확합니다! 여기에 짝꿍 함정으로 정규화(논리적 설계 단계) vs 반정규화(물리적 설계 단계)의 구분을 얹어두시면 완벽합니다."

### 📌 [Q02 (전체 52번)] 관계대수(Relational Algebra) 연산자 분류 체계

**📋 문제 본문 및 보기:**
```text
다음 관계대수(Relational Algebra) 연산자 중 순수 관계 연산자에 해당하지 않는 것은?

① 셀렉션(Selection)
② 프로젝션(Projection)
③ 디비전(Division)
④ 합집합(Union)
```

**🎯 정답:** ④번 (합집합)

#### 💬 실시간 1:1 심층 대화 전문 (Full Dialogue)
* **🧑‍💻 [매니저님]**: "일반 집합하고 순수 관계가 다르구나. 일반 집합은 테이블이 2개 이상 있어야만 가능한거 같고, 순수 관계는 조인을 제외하면 혼자서도 할 수 있는거네"
* **🎓 [임선우 코치]**: "와, 매니저님! 관계대수의 또 다른 핵심 분류 축인 **'단항 연산자(Unary) vs 이항 연산자(Binary)'**의 본질을 정확히 꿰뚫어 보셨습니다!
  * 단항 연산자 (테이블 1개): 셀렉션($\sigma$), 프로젝션($\pi$)
  * 이항 연산자 (테이블 2개 필수): 일반 집합 4종 전체(합·교·차·카티션 곱) + 순수 관계 중 조인($\bowtie$)과 디비전($\div$)
  혼자서 할 수 있는 단항 연산자는 오직 셀렉션과 프로젝션 둘뿐입니다."
* **🧑‍💻 [매니저님]**: "디비전은 뭐하는거지?"
* **🎓 [임선우 코치]**: "디비전($R \div S$)은 '상대방 테이블($S$)에 적힌 조건을 모두(ALL) 만족하는 대상을 골라내는 연산자'입니다. 예를 들어 '이번 학기 필수과목(DB, OS)을 모두 수강한 학생'을 찾을 때 사용합니다. 차수는 $R$의 속성에서 $S$의 속성을 뺀 나머지만 남으며, SQL에서는 `NOT EXISTS`의 이중 부정 서브쿼리나 `GROUP BY + HAVING COUNT()`로 구현합니다."
* **🧑‍💻 [매니저님]**: "다시 정리하면 일반 집합 연산자는 합집합, 교집합, 차집합, 곱하기가 있고 순수 관계 연산자는 셀렉션, 프로젝션, 디비전, 조인이 있다"
* **🎓 [임선우 코치]**: "완벽합니다! 100점 만점의 정확한 정리입니다."

### 📌 [Q03 (전체 53번)] SQL 집계함수(Aggregate Functions)와 NULL 처리 원칙

**📋 문제 본문 및 보기:**
```text
다음 SQL문과 릴레이션 R의 데이터에 대한 실행 결과로 가장 적절한 것은?

[릴레이션 R]
| A | B |
|---|---|
| 1 | 10 |
| 2 | NULL |
| 3 | 20 |
| 4 | NULL |
| NULL | 30 |

[SQL]
SELECT COUNT(*), COUNT(A), COUNT(B), SUM(B), AVG(B)
FROM R;

① 5, 4, 3, 60, 20
② 5, 5, 5, 60, 12
③ 4, 4, 3, 60, 20
④ 5, 4, 3, NULL, NULL
```

**🎯 정답:** ①번

#### 💬 실시간 1:1 심층 대화 전문 (Full Dialogue)
* **🧑‍💻 [매니저님]**: "이 문제는 null값 때문에 헷갈리는건데 일단 summary함수는 null을 제외하고 계산한다는 원칙이 있지 않나"
* **🎓 [임선우 코치]**: "네, 정확합니다! 모든 집계함수는 기본적으로 NULL을 배제합니다. 유일한 예외는 행의 개수 자체를 카운트하는 `COUNT(*)`뿐입니다."
* **🧑‍💻 [매니저님]**: "일단 이 문제를 보면 sum함수는 null을 제외하고 더하는 것으로 알고 있으니까 각 보기의 4번째 항목인 sum(B)는 60이 된다(4번 탈락), 어떤 값을 null로 나눌 수 없으니까 avg(B)는 null이 아닌 항목의 합으로 나눌것이므로 avg(B)는 60/3이라서 20(2번 탈락), count(A), count(B)는 4, 3으로 동일하니까 제쳐두고 count(*)만 봤을 때 null을 포함한 5개냐, null을 제외한 4개냐의 싸움. A, B컬럼이 모두 null이면 좀 헷갈렸을 수 있지만 하나가 null이더라도 다른 컬럼에는 값이 있으므로 5개"
* **🎓 [임선우 코치]**: "소거법 실전 전략이 정말 예술입니다! 여기서 매니저님께서 짚으신 '만약 한 행의 모든 컬럼(A, B 둘 다)이 NULL이면?'이라는 의문에 대해: **모든 컬럼이 NULL이어도 `COUNT(*)`는 무조건 카운트합니다!** `COUNT(*)`는 컬럼 값을 전혀 보지 않고 '물리적 행(Row)의 존재 수'만 세기 때문입니다."

### 📌 [Q04 (전체 54번)] 동시성 제어 이상현상과 연쇄 복귀(Cascading Rollback)의 본질

**📋 문제 본문 및 보기:**
```text
동시성 제어(Concurrency Control)가 적절히 이루어지지 않을 때 발생할 수 있는 문제점으로 가장 적절하지 않은 것은?

① 갱신 분실(Lost Update): 두 개 이상의 트랜잭션이 같은 데이터를 공유하여 갱신할 때 일부 갱신 결과가 사라지는 현상
② 모순성(Inconsistency): 복수의 트랜잭션이 동시에 실행되어 데이터베이스의 일관성이 결여되는 현상
③ 연쇄 복귀(Cascading Rollback): 한 트랜잭션이 롤백될 때 해당 트랜잭션이 수정한 데이터를 참조한 다른 트랜잭션도 연쇄적으로 롤백되는 현상
④ 교착상태(Deadlock): 트랜잭션이 영구적으로 자원을 점유하여 다른 모든 트랜잭션이 정상 완료되는 현상
```

**🎯 정답:** ④번

#### 💬 실시간 1:1 심층 대화 전문 (Full Dialogue)
* **🧑‍💻 [매니저님]**: "아놔... 정상 완료되는 현상이라는 말이 숨어 있었네"
* **🎓 [임선우 코치]**: "출제위원들의 전형적인 꼬리 왜곡(Tail Trap) 함정입니다. 전문 용어로 시작해 방심하게 한 뒤 문장 맨 끝 서술어를 뒤집는 수법입니다."
* **🧑‍💻 [매니저님]**: "갱신 분실은 보기에 있는 내용처럼 동시에 수정하려할 때 하나만 반영되는 현상인것 같고, 모순성은 여기저기 동시에 수정하다가 값이 안맞는 현상을 말하는거 같네"
* **🎓 [임선우 코치]**: "네! 갱신분실은 나중에 쓴 트랜잭션이 앞선 갱신을 덮어써 사라지는 현상이고, 모순성은 트랜잭션 진행 도중의 미완료 중간 상태를 읽어 합계가 안 맞는 현상입니다."

* **🎓 [임선우 코치]**: "네, 맞물려 멈춰버리는 원형 대기(Circular Wait)가 진짜 데드락의 정의입니다."
* **🧑‍💻 [매니저님]**: "연쇄복귀는 한 트랜잭션이 취소될 때 그와 관련된 다른 트랜잭션들도 줄줄이 취소되는 현상인가"
* **🎓 [임선우 코치]**: "네, 도미노가 연쇄적으로 쓰러지는 현상과 같습니다."
* **🧑‍💻 [매니저님]**: "그런데 이건 문제점이라기보다는 취소되어야 하는 현상 아닌가? 아직 확정되지 않은 데이터를 가지고 뭔가를 하고 있었다가 확정되지 않은 데이터가 롤백되면 뭔가 하고 있는것도 취소되어야 하는데, 그냥 진행되면 안되잖아"
* **🎓 [임선우 코치]**: "정말 감탄이 나올 정도로 날카로운 지적이십니다! 취소해 주는 수습 행위 자체는 정합성을 위해 당연한 것입니다. 다만 학계에서 이를 '문제점'으로 부르는 이유는: 1) 수십 개 트랜잭션의 연산 자원을 헛되이 날리는 시스템 재앙이고, 2) 만약 뒤 트랜잭션이 먼저 커밋해 버리면 복구 불가능한 영구 데이터 오염(회복 불가능 스케줄)이 터지기 때문입니다. 그래서 '애초에 남의 미확정 데이터는 쳐다보지도 못하게 락을 쥐고 있자(Strict 2PL, 비연쇄 스케줄)'는 철학이 나왔습니다."
* **🧑‍💻 [매니저님]**: "그러니까 이건 발생하지 않게 해야 하는 현상인거지, 발생해서 복구하는 것 자체가 문제점은 아닌거 같다는거지"
* **🎓 [임선우 코치]**: "100% 맞습니다! 복구 행위가 문제가 아니라, 동시성 제어를 부실하게 해서 멀쩡한 트랜잭션들까지 연쇄 롤백당해야 하는 불행한 상황 자체가 문제입니다."
* **🧑‍💻 [매니저님]**: **"암에 걸리지 않도록 조심하는건 맞는데 암에 걸렸는데 배를 가르는 수술을 하는건 너무 심각한 문제가 된다 라고 하는거잖아"**

```text
① 완전성(Completeness): 데이터 항목에 누락된 값(Null 또는 공백) 없이 필수 데이터가 모두 충족되어 있는 정도
② 정확성(Accuracy): 데이터가 실제 현실 세계의 대상 값과 일치하는 정확한 정보를 표현하고 있는 정도
③ 일관성(Consistency): 여러 시스템이나 테이블 간에 동일한 데이터가 모순 없이 동일하게 유지되는 정도
④ 유효성(Validity): 데이터의 물리적 저장 공간 크기가 디스크 허용 한도를 초과하지 않는 정도
```

**🎯 정답:** ④번 (유효성은 도메인, 데이터 형식, 정규식 패턴 준수 여부이며, 디스크 한도는 하드웨어 용량 관리 영역임)

```text
관계형 데이터 모델의 무결성 제약조건(Integrity Constraints)에 대한 설명으로 가장 적절하지 않은 것은?

① 개체 무결성(Entity Integrity): 기본키(Primary Key)를 구성하는 어떤 속성도 NULL 값이나 중복 값을 가질 수 없다.

③ 도메인 무결성(Domain Integrity): 특정 속성의 값은 해당 속성에 정의된 도메인(데이터 타입, 허용 범위 등)에 속한 값이어야 한다.
④ 고유 무결성(Unique Integrity): 릴레이션의 모든 일반 속성은 서로 다른 값을 가져야 하며 중복이 전면 금지된다.
```

### 📌 [Q22 (전체 72번)] RDBMS 3대 조인 알고리즘과 해시 조인 제약

**📋 문제 본문 및 보기:**
```text
관계형 데이터베이스의 주요 조인(Join) 알고리즘에 대한 설명으로 가장 적절하지 않은 것은?

① 중첩 루프 조인(Nested Loop Join): 외부 테이블의 각 행마다 내부 테이블을 반복 검색하는 방식으로 소량 데이터 처리에 유리하다.
② 정렬 병합 조인(Sort Merge Join): 양쪽 테이블을 조인 키 기준으로 먼저 정렬한 후 병합하는 방식으로 동등 조인과 비동등 조인 모두 적용 가능하다.
③ 해시 조인(Hash Join): 빌드 입력 테이블로 해시 테이블을 생성하고 프로브 테이블을 스캔하여 매칭하며 대용량 동등 조인(=)에 효과적이다.
④ 해시 조인(Hash Join): 부등호(<, >) 및 범위 검색과 같은 비동등 조인(Non-Equi Join) 연산에 가장 최적화되어 있다.
```

**🎯 정답:** ④번 (해시 함수는 값의 대소 관계를 보존하지 않으므로 오직 동등 조인(=)만 가능하며 비동등 조인은 절대 불가함)
