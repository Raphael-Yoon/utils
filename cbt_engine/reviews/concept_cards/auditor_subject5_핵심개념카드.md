### 핵심 포인트 요약
- 공개키 암호: ElGamal은 이산대수 문제 기반, 일회용 난수 k를 사용해 암호문이 (c1, c2) 두 성분으로 구성되어 평문 대비 약 2배로 확장(평문·암호문 길이가 같다는 서술은 오답). RSA는 소인수분해 난제 기반 안전성(양자컴퓨팅 등장 시 위협 가능). 공개키는 N명 기준 2N개의 키만 필요해(대칭키는 N(N-1)/2개) 키 관리 개수가 대폭 절감되지만, 연산 속도는 대칭키보다 100~1000배 느림.
- 해시 함수: 무결성 검증·전자서명에는 사용되나 복호화 기능이 없어 기밀성은 보장하지 못함. 역상저항성(일방향성)/제2역상저항성(약한 충돌저항성)/강한 충돌저항성 3대 속성 구분.
- 블록암호 운용모드: CBC(이전 암호문과 XOR, 암호화는 순차적이라 병렬처리 불가하나 복호화는 병렬 가능) / CTR(암호화·복호화 모두 병렬 처리 가능) / GCM(CTR 기반 + GHASH 연산으로 기밀성과 무결성/인증을 동시 제공하는 AEAD 방식).
- SSL/TLS: 핸드셰이크 프로토콜(상호 인증, 암호화 스위트 협상, 세션 키 교환 담당) vs 레코드 프로토콜(응용 데이터 단편화·압축·MAC 계산·대칭키 암호화 담당) — 역할이 자주 뒤바뀌어 출제.
- VPN 터널링: L2TP(자체 암호화 없음, IPsec과 결합해 기밀성·인증 제공) / SSTP(HTTPS 443 포트로 SSL/TLS 세션) / PPTP(2계층, PPP 확장). IPsec 전송모드(Payload만 암호화, 기존 IP헤더 유지) vs 터널모드(IP패킷 전체 암호화 후 새 IP헤더로 캡슐화) — 두 모드 설명이 자주 뒤바뀌어 출제.
- 하이브리드 암호 시스템: 메시지 본문은 대칭키(세션키)로 암호화, 세션키 자체는 수신자의 공개키로 암호화해 전달.
- HMAC: 무결성과 출처 인증은 제공하지만, 송수신자가 동일 비밀키를 공유하므로 부인방지(제3자 증명)는 제공하지 못함.
- DB 암호화 방식: API 방식(WAS 서버에 라이브러리 형태로 설치, 응용프로그램이 직접 호출) vs Plug-In 방식(DB 서버 내부에 설치, 응용프로그램 수정 거의 불필요).
- 블록체인: 해시체인+분산합의로 데이터 불변성(Immutability) 보장 — 과거 트랜잭션을 직접 삭제하지 못하며 정정 시 새로운 역거래(보상 트랜잭션)를 추가. 동형암호(Homomorphic Encryption)는 복호화 없이 암호화 상태로 연산 가능해 클라우드 민감정보 처리에 오히려 적합(부적합하다는 서술은 오답).

### 연도별 출제 형식

- 2024: 보안솔루션(DLP/DRM/안티스팸) 매칭형, GCM 운용모드 오답찾기형, VPN 솔루션 판별형, 공개키암호 오답찾기형, HMAC 오답찾기형, 하이브리드 암호시스템 오답찾기형, 블록체인 공격유형 오답찾기형

- 2022: 전자서명 역할 오답찾기형, MAC(CBC-MAC) 개념 판별형, 가명정보 보호조치 오답찾기형, DLP 개념 판별형, VPN 프로토콜(PPTP) 오답찾기형

### 오답 함정 / 헷갈리는 개념 구분
- CBC(암호화는 순차적, 복호화만 병렬 가능) vs CTR/GCM(암·복호화 모두 병렬 가능) — 병렬처리 가능 여부를 반대로 서술하는 함정 반복.
- IPsec 전송모드/터널모드의 암호화 범위(Payload만 vs IP패킷 전체)가 자주 뒤바뀌어 출제.
- API 방식 vs Plug-In 방식 DB암호화의 설치 위치(WAS 서버 vs DB 서버)를 혼동하지 않도록 주의.
- 해시 함수는 무결성만 제공하고 기밀성은 제공하지 못함 — "해시로 기밀성을 보장한다"는 서술은 오답.

## 2. 인증/접근통제

### 5개년 출제 현황

| 연도 | 2022 | 2023 | 2024 | 2025 | 2026 | 합계 | 출제 개년수 | 빈출도 |

| 문항수 | 4 | 3 | 8 | 4 | 3 | 22 | 5/5 | ★★★★★ |

### 핵심 포인트 요약
- OWASP API Security Top 10: Broken Object Level Authorization(객체 식별자 조작으로 타인 리소스 접근) vs Broken Authentication(인증 체계 구현 미흡으로 토큰·세션 탈취/위장).
- 제로 트러스트(Zero Trust, NIST SP 800-207): "Never Trust, Always Verify" — 기존 경계 기반(Perimeter) 보안모델의 한계를 극복하기 위해 등장. "경계 기반 보안을 더욱 강화해야 한다"는 서술은 제로 트러스트 철학과 정반대이므로 오답.
- NAC(Network Access Control): MAC 주소 인증 + 백신 설치·OS 패치 등 보안정책 준수 여부를 검증해 네트워크 접근을 통제.
- SSO(Single Sign-On): 중앙 인증서버로 1회 인증 후 재인증 없이 연동 시스템 전체 접근 가능 — 중앙 서버 장애 시 전체 인증이 마비되는 SPOF(단일 장애점) 위험을 내포.
- 스푸핑 공격 구분: ARP 스푸핑(위조 ARP Reply로 ARP 캐시테이블의 IP-MAC 매핑 변조) vs IP 스푸핑(출발지 IP 위조) vs ICMP 리다이렉트.
- 생체 인증: 인증 전 반드시 생체 템플릿을 서버/DB에 사전 등록(Enrollment)해야 하며, 인증 시 입력값과 등록 템플릿 간 매칭 스코어를 비교 — "등록 없이 인증 가능"은 오답.
- 보안 거버넌스: 비즈니스 전략과 연계한 보안 정책 수립·조직 구성·자원 배분을 총괄하는 전사적 프레임워크(권한관리·위험분석·접근통제와는 구분되는 상위 개념).
- 가명정보 접근권한: 최소 인원으로 제한 지정하고 업무·역할별로 차등 부여(균등 부여는 오답).
- RBAC(역할기반 접근통제): 사용자에게 직접 권한을 주지 않고 역할(Role)에 권한을 할당해 간접적으로 접근을 관리.

### 연도별 출제 형식
- 2026: API 보안취약점(OWASP) 짝짓기형, 블록체인+IoT 판별형(암호화 개념과 중복), TLS 오답찾기형(암호화 개념과 중복)
- 2025: SSL/TLS 핸드셰이크형(암호화 개념과 중복), VPN 프로토콜형(암호화 개념과 중복), NAC 판별형, 가명정보 보호조치 오답찾기형
- 2024: 제로트러스트 오답찾기형, 보안솔루션 매칭형(암호화 개념과 중복), GCM형(암호화 개념과 중복), 스푸핑(ARP) 판별형, SSO 오답찾기형, HMAC형(암호화 개념과 중복), 생체인증 오답찾기형

### 오답 함정 / 헷갈리는 개념 구분
- 이 개념은 원본 데이터에서 암호화·네트워크보안 개념과 문항이 다수 겹쳐 태깅됨(한 문항이 VPN/TLS/블록체인 등을 다루며 여러 개념에 동시 포함). 순수 "인증/접근통제" 고유 포인트는 OWASP API 취약점, 제로트러스트, NAC, SSO, ARP 스푸핑, 생체인증, RBAC 위주로 압축해 학습하는 것이 효율적.
- "경계 기반 보안체계를 더욱 강화해야 한다"는 제로 트러스트 문제의 단골 오답 — 제로 트러스트는 경계 기반 모델을 대체하려는 개념.
- 생체인증은 사전 등록(Enrollment) 필수 — "등록 없이 인증 가능"은 항상 오답.

## 3. 네트워크보안(방화벽/IDS)

### 5개년 출제 현황

| 연도 | 2022 | 2023 | 2024 | 2025 | 2026 | 합계 | 출제 개년수 | 빈출도 |
|---|---|---|---|---|---|---|---|---|
| 문항수 | 4 | 2 | 5 | 4 | 3 | 18 | 5/5 | ★★★★★ |

### 핵심 포인트 요약
- 웹 애플리케이션 DoS 공격 유형: Slow HTTP(헤더/본문 전송을 느리게 해 연결을 점유) / GET Flooding(대량 요청으로 자원 소모) / Dynamic HTTP Request Flooding(동적 페이지를 지속 요청해 서버 자원 소모) — 이는 "재생(Replay) 공격"과는 성격이 다른 별개의 공격 유형(둘을 혼동하면 오답).
- 방화벽: 패킷 필터링 방화벽은 IP·포트·프로토콜 등 헤더 정보만으로 허용/차단을 결정하며 페이로드(payload) 내용은 분석하지 않음 — 페이로드까지 분석하는 심층패킷검사(DPI)는 애플리케이션 방화벽 등에서 수행.
- 블랙홀 필터링(Null Routing): 악성 트래픽을 가상의 Null 인터페이스로 보내 조용히 폐기(Drop) — Ingress 필터링(외부→내부 차단), Egress 필터링(내부→외부 차단), Unicast RPF(소스 IP 유효성을 역경로로 검증)와 구분.
- IoT 보안 위협: 비동기화 공격(De-synchronization Attack, 위조된 타임스탬프로 재동기화 자원을 낭비시키는 DoS성 공격)을 Spoofing(신원 위장)/Sybil(다수 가짜 ID)/Eavesdropping(도청)과 구분.
- SAST(정적 분석) 도구: SpotBugs(자바 바이트코드 분석, XSS·경로탐사·하드코딩 비밀번호 등 탐지) vs ModSecurity(오픈소스 WAF) vs OpenVAS(동적 취약점 스캐너) vs OllyDbg(바이너리 동적 디버깅/리버스 엔지니어링).
- Snort 룰: 탐지만 하는 `alert`와 차단까지 하는 `drop`/`reject`를 구분, 출발지 IP는 NOT 연산자(`!`)로 "내부망 제외" 표현.
- Confusion Matrix(오탐/미탐): 정상 접근을 공격으로 오인(False Positive)하면 가용성이 침해됨 — TP/TN/FP/FN 정의를 정확히 구분.
- iptables: `-A INPUT -s [IP] -j DROP` 형태로 특정 출발지 IP를 차단.

- 2026: DoS 공격유형 오답찾기형, 방화벽(패킷필터링 vs DPI) 오답찾기형, TLS형(암호화 개념과 중복)
- 2025: 블랙홀 필터링 판별형, VPN형(암호화 개념과 중복), IoT 비동기화 공격 판별형, SAST 도구(SpotBugs) 판별형
- 2024: 제로트러스트형(인증/접근통제 개념과 중복), Snort 룰 작성형, VPN형(암호화 개념과 중복), Confusion Matrix(오탐) 개념형, 블록체인 공격형(암호화 개념과 중복)

- 2022: 방화벽 패킷필터링 규칙표 해석형, iptables 명령어형, 클라우드 보안위협 오답찾기형, VPN 프로토콜형(암호화 개념과 중복)

### 오답 함정 / 헷갈리는 개념 구분
- Dynamic HTTP Request Flooding은 재생(Replay) 공격과 성격이 다름 — 두 개념을 같은 것처럼 서술하면 오답.
- 패킷 필터링 방화벽은 페이로드를 분석하지 않음 — DPI(애플리케이션 방화벽 기능)와 혼동 주의.
- False Positive(정상을 공격으로 오탐)는 가용성 침해의 원인 — Confusion Matrix 용어 정의를 정확히 구분해야 함.

### 핵심 포인트 요약
- 개인정보 유출 통지 사항(법 제34조): 유출된 개인정보 항목, 유출 시점과 경위, 피해 최소화를 위해 정보주체가 할 수 있는 방법, 개인정보처리자의 대응조치·피해구제절차, 신고 접수 담당부서·연락처 — "유출된 개인정보의 규모 및 피해액"은 법정 통지 항목에 포함되지 않음.
- 제3자 제공 동의 시 고지사항(법 제17조②): 제공받는 자, 이용 목적, 제공 항목, 보유·이용 기간, 동의 거부 권리 및 불이익 — "정보제공 시 사용하는 보안조치"는 법정 고지사항이 아님.
- 가명정보 처리 특례(법 제28조의2~5): 통계작성·과학적연구·공익적 기록보존 목적이면 정보주체 동의 없이 가명정보 처리 가능. 처리 과정에서 특정 개인을 알아볼 수 있는 정보가 생성되면 즉시 처리를 중지하고 지체 없이 회수·파기해야 함("정보주체에게 통지 후 계속 처리 가능"은 오답).
- 가명정보 기술적 보호조치: 추가정보와 가명정보는 분리해 저장·관리하되 반드시 물리적 분리일 필요는 없음(논리적 분리도 허용). 접근 가능 인원은 업무상 필요한 최소 인원으로 제한하고 역할별 차등 권한 부여(균등 부여는 오답).
- 개인정보 영향평가(PIA, 법 제33조): 개인정보 침해가 우려되는 경우 위험요인을 사전에 분석·개선하는 사전적 평가 절차 — "법정 보유기간 경과 기록을 삭제하는 사후 절차"라는 서술은 오답. 고려사항에는 처리하는 개인정보 수, 제3자 제공 여부, 정보주체 권리 침해 가능성, 민감·고유식별정보 처리 여부, 보유기간 등이 포함(2025년 117번은 4개 보기 모두가 고려사항에 해당해 "전체정답"으로 처리된 사례 존재).
- 동의 획득 방법(시행령 제17조): 전화로 동의 내용을 알리고 인터넷주소로 확인하게 한 경우, 이후 다시 전화로 동의 의사표시를 재확인하는 절차까지 거쳐야 적법.
- 개인정보 보호 원칙(법 제3조): 처리 목적을 명확히 하고 그 범위에서 최소한의 정보만 수집해야 함("목적을 명확히 하지 않아도 된다"는 오답).

### 연도별 출제 형식
- 2026: 유출통지 등 법령 진위 복합판별형, 동의 방법(시행령 제17조) 오답찾기형
- 2025: 개인정보 영향평가 고려사항형(전체정답 처리 사례), 제3자 제공 고지사항 오답찾기형, 가명정보 보호조치 오답찾기형
- 2024: 가명정보 처리특례 오답찾기형, 유출 통지사항 오답찾기형
- 2023: 개인정보 보호원칙 오답찾기형
- 2022: 가명정보 보호조치형(암호화 개념과 중복 태깅)

### 오답 함정 / 헷갈리는 개념 구분
- 유출 통지 사항에는 "피해 규모·피해액"이 없음 — 5가지 법정 항목(항목/시점경위/피해최소화방법/대응조치및구제절차/신고접수처)만 정확히.
- 제3자 제공 고지사항에는 "보안조치 내용"이 없음 — 5가지 법정 항목(제공받는자/이용목적/제공항목/보유기간/동의거부권리및불이익)만 정확히.
- 개인정보 영향평가는 "사전적" 평가 절차 — "보유기간 경과 기록 삭제"라는 사후 절차와 혼동 금지.
- 가명정보 처리 중 특정 개인 식별 가능 정보가 생성되면 "즉시 중지+회수파기"가 원칙 — "통지 후 계속 처리"는 항상 오답.
- 2025년 117번처럼 보기 4개가 모두 옳아 "전체정답"으로 처리된 사례가 있어, 정답 판정 자체가 예외적으로 변경될 수 있음에 유의(원본 해설 확인 권장).
