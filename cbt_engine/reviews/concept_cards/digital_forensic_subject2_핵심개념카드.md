### 1. 파일시스템구조(FAT/NTFS) - ★★★ (총 29문항, 3회 모두 출제 / 과목2 최다빈출)

**핵심 포인트**
- FAT32 물리 레이아웃: 예약 영역(VBR 포함) → FAT#1 → FAT#2(백업본) → 데이터 영역(Data Area) 순서.
- FAT32 삭제: 디렉터리 엔트리 첫 바이트가 0xE5로 변경, FAT 체인은 0으로 초기화되지만 나머지 메타데이터(시간/크기 등)는 덮어써지기 전까지 보존.
- NTFS 시스템 예약 메타파일: $MFT, $LogFile, $Volume, $Bitmap, $Boot, $BadClus 등. $DATA는 별도 파일이 아니라 MFT 엔트리 내부의 "속성(Attribute)"이므로 혼동 주의.
- Resident(상주) vs Non-Resident(비상주): 데이터가 작으면(약 680바이트 이하) MFT 엔트리 내부에 직접 저장(Resident), 크면 외부 클러스터에 저장하고 데이터 런(Data Run)으로 매핑(Non-Resident).
- $STANDARD_INFORMATION(SI)과 $FILE_NAME(FN) 타임스탬프 비교: 일반 안티포렌식 툴은 SI만 위조 가능하고 FN은 커널 레벨 관리라 위조가 어려워, 둘을 비교하면 시간 위조를 탐지할 수 있다.
- exFAT는 FAT32의 4GB 파일 크기 제한을 극복했지만 NTFS 수준의 ACL 보안이나 저널링 기능은 없다.
- 슬랙 공간 3종: 볼륨 슬랙(파티션 경계 밖 낭비 영역, 가상메모리와 무관), RAM 슬랙(파일 끝부터 섹터 끝까지, 메모리 잔여 데이터 가능성), 드라이브/파일 슬랙(섹터 끝부터 클러스터 끝까지).

**회차별 출제 형식**
- 1회: FAT32 레이아웃/삭제 흔적, exFAT 특징, MFT 시스템 파일 구분, Resident 개념, SI/FN 비교, 슬랙 공간 정의, MBR 파티션 타입 코드(0x07=NTFS/exFAT) 등 개념 정의 위주.
- 2회: $MFT/$LogFile/$Secure 등 개별 메타파일 역할, RAM 슬랙/드라이브 슬랙 실제 바이트 계산 문제, $UsnJrnl(USN 저널) 등 응용 계산·실무형 문제.
- 3회: FAT 체인 포인터, $Bitmap, MFT Flags(0x01/0x02/0x00), Data Run, 8.3 레지스트리 설정, Offset to Content, $BadClust 등 심화 세부 구조 문제.

**오답 함정/헷갈리는 개념**
- $DATA는 시스템 메타파일이 아니라 파일 데이터를 담는 "속성"이라는 점.
- SI와 FN 중 어느 쪽이 위조되기 쉬운지 반대로 알면 오답($SI가 위조되기 쉬움, $FN은 어려움).
- $LogFile(파일시스템 무결성 트랜잭션 로그)과 $UsnJrnl(사용자 행위 변경 이력 저널)의 용도 구분.
- 볼륨 슬랙은 가상 메모리 스왑과는 무관한 개념.

### 2. 프로세스/스레드/스케줄링 - ★★ (총 8문항, 3회 모두 출제)

**핵심 포인트**
- SSTF(Shortest Seek Time First): 현재 헤드 위치에서 가장 가까운 트랙 요청을 우선 처리. FCFS보다 처리율은 높지만 바깥 트랙 요청이 계속 밀리는 기아(Starvation) 현상 우려.
- 디스패치(Dispatch): 준비(Ready) 큐의 프로세스가 스케줄러에 의해 선택되어 CPU 실행 권한을 획득하는 전이 과정.
- 데드락(교착상태) 4대 필요조건: 상호배제, 점유와 대기, 비선점(No Preemption), 환형 대기. 선점이 허용되면 데드락은 자연 해소된다.
- 페이지 폴트(Page Fault): 필요한 페이지가 물리 메모리에 없어 보조기억장치에서 읽어와야 할 때 발생하는 인터럽트.
- C-SCAN: SCAN의 파생 기법으로, 한 방향으로만 진행하다 마지막 트랙에서 처음 트랙으로 wrap-around 후 동일 방향으로 재진행.

**회차별 출제 형식**
- 1회: SSTF, 디스패치, 데드락 4대 조건 등 기본 개념 문제.
- 2회: SSTF 재확인, 페이지 폴트 정의 문제.
- 3회: C-SCAN, Ready 상태 정의, (파일시스템과 연계된) 레지스트리 설정 문제.

**오답 함정/헷갈리는 개념**
- SSTF의 부작용인 기아(Starvation) 현상을 놓치기 쉬움.
- 데드락 4대 조건 중 "비선점"과 "선점"을 반대로 서술하는 함정.
- SCAN과 C-SCAN의 차이(C-SCAN은 단방향 스윕 + wrap-around).

### 3. 삭제파일복구/카빙 - ★★ (총 6문항, 3회 모두 출제)

**핵심 포인트**
- FAT32 삭제 시 디렉터리 엔트리 첫 바이트가 0xE5로 변경되는 흔적(파일시스템구조 파트와 연동 출제).
- 데이터 카빙(Data Carving): 파일시스템 메타데이터 없이 파일 고유 시그니처(헤더/푸터, 예: JPEG의 FF D8 FF)를 스캔해 비할당 영역의 파일을 복구하는 기법.
- exFAT는 FAT32 대비 대용량 지원은 강화됐지만 NTFS 수준 저널링/ACL은 없음(재등장 포인트).
- 스마트 카빙(파편화 복구 카빙): 파일이 여러 조각으로 흩어졌을 때 내부 구조적 문맥(예: HTML 태그 일치)으로 순차 재조합하는 고급 기법.
- 파일 푸터 시그니처: PDF는 %%EOF, ZIP은 EOCD(50 4B 05 06), PNG는 IEND(49 45 4E 44 AE 42 60 82).

**회차별 출제 형식**
- 1회: FAT32 삭제 흔적 문제.
- 2회: $LogFile, 데이터 카빙 정의, exFAT 비교 문제.
- 3회: 스마트 카빙(파편화 복구), 파일 푸터 시그니처 매칭 문제.

**오답 함정/헷갈리는 개념**
- 파일 포맷별 헤더/푸터 시그니처를 정확히 매칭해야 하며 유사 헥스값(PDF %%EOF 등)에 유의.

### 4. 레지스트리분석 - ★ (총 3문항, 1·3회 출제)

**핵심 포인트**
- 슬랙 공간 정의 문항과 연동 출제(파일시스템구조 파트 참고).
- 레지스트리 하이브 파일 중 NTUSER.DAT는 현재 로그인한 개별 사용자 프로필 정보와 활동 흔적을 보관.
- NtfsDisable8dot3NameCreation 레지스트리 값을 1로 설정하면 8.3 단축 파일명 생성을 억제해 입출력 오버헤드를 줄인다.

**회차별 출제 형식**
- 1회: 하이브 파일과 물리 파일의 매칭 문제(슬랙 공간 정의 문제와 동시 출제).
- 3회: 8.3 표기 규칙 억제 레지스트리 키워드를 묻는 문제.

**오답 함정/헷갈리는 개념**
- NTUSER.DAT는 시스템 전체가 아니라 "개별 로그인 사용자"의 프로필 정보를 담는다는 점.

### 5. 윈도우아티팩트 - ★ (총 2문항, 1·2회 출제)

**핵심 포인트**
- ext2의 inode 구조체에는 파일 삭제 시각을 기록하는 'Deletion Time' 필드가 있지만, NTFS MFT 속성에는 이런 전용 삭제 시각 필드가 없어 USN 저널·이벤트 로그 등 다른 흔적으로 추론해야 한다.
- FAT32에서 파일을 완전 삭제(Shift+Delete)하면 디렉터리 엔트리 파일명 첫 바이트가 0xE5로 채워진다.

**회차별 출제 형식**
- 1회: ext2 inode와 NTFS MFT 비교 문제.
- 2회: FAT32 완전 삭제 시 상태 마크 변경값을 묻는 문제.

**오답 함정/헷갈리는 개념**
- NTFS는 ext2와 달리 전용 "삭제 시각" 필드가 없다는 점 - 있다고 오인하기 쉬움.
