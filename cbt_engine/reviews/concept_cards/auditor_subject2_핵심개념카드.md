### 핵심 포인트 요약
- **UML 4대 관계선 표기법**:
  - 실체화(Realization, `implements`): 점선 + 속이 빈 삼각형 `◁..`
  - 일반화(Generalization, `extends`): 실선 + 속이 빈 삼각형 `◁─`
  - 연관(Association, 객체 소유): 실선 화살표 `─➔` (다중성 `*` 표기 필수)
  - 의존(Dependency, 일시 사용): 점선 화살표 `..➔`
- **시퀀스 다이어그램 복잡도(CC) 및 결합도(CBO) 산출**:
  - **순환복잡도 (CC)** = 분기 프래그먼트 수(`loop`, `break`, `opt`, `alt`) + 1
  - **클래스 결합도 (CBO)** = 직접 호출/결합된 **'클래스(타입)의 종류 수'** (동일 클래스의 인스턴스 객체가 여러 개여도 1개로 계산하는 것이 킬러 함정!)
- **시퀀스-클래스 일관성 검증 4대 체크리스트**:
  1. `for each, c2s` ➔ 클래스 다이어그램 연관관계에 **`*` 다중성 표기** 필수
  2. 자식 클래스에 메서드가 안 보일 때 ➔ **부모 클래스의 상속 메서드** 여부 확인
  3. 자기 자신 호출(Self-call) ➔ **private `-`** 접근 제어자 확인
  4. 메서드 파라미터 일시 전달 ➔ **점선 의존(`..>`)** 관계 확인
- **로버트 마틴의 클린 아키텍처(Clean Architecture) 4계층 순서 및 의존성 규칙**:
  - 계층 순서 (안쪽 ➔ 바깥쪽): **`Entities ➔ Use Cases ➔ Interface Adapters ➔ Frameworks & Drivers`**
  - 의존성 규칙(Dependency Rule): 소스코드 의존성은 **반드시 바깥쪽(도구/프레임워크)에서 안쪽(순수 비즈니스 엔티티)으로만** 향해야 하며, 안쪽 코드는 바깥쪽 기술을 절대 몰라야 함.
- **State Machine 액션 순서**:
  - "서브상태 exit → 이벤트 트리거 액션 → 슈퍼상태 exit → 전이 액션 → 타겟상태 entry" 순서.

### 연도별 출제 형식
- 2026: Java 코드 → UML 표기법 매칭형, 시퀀스다이어그램 조합조각(break) 실행흐름 추적형, 클래스다이어그램 → 객체지향 개념 묶음 판별형, State Machine 액션값 추적 계산형
- 2025: 시퀀스다이어그램 → 디자인패턴(Master-Slave) 판별형, Java 코드 → 클래스다이어그램 매칭형, SysML 요구사항 관계 보기선택형, State Machine 액션순서형, 유스케이스 확장관계형
- 2024: UML 다이어그램 유형(Activity Diagram) 판별형, SysML 다이어그램 특징 판별형, 리팩토링(Type Code 대체) 사례형, 요구사항 추출방법 판별형
- 2023: SysML-UML 공통 다이어그램 판별형, State Machine 복합상태 이탈 액션순서형
- 2022: Clean Architecture 4계층 순서형, 디자인패턴 복합 판별형(Command+Adapter), 시퀀스-클래스다이어그램 다중성 오류 판별형, CC/CBO 계산형

## 2. 소프트웨어 테스트 및 품질·신뢰성 공학

### 5개년 출제 현황

| 연도 | 2022 | 2023 | 2024 | 2025 | 2026 | 합계 | 출제 개년수 | 빈출도 |
|---|---|---|---|---|---|---|---|---|
| 문항수 | 1 | 2 | 4 | 3 | 2 | 12 | 5/5 | ★★★★★ |

### 핵심 포인트 요약
- **변형 조건/결정 커버리지 (MC/DC)**:
  - 각 조건식이 전체 결정 결과에 독립적으로 영향을 미치는 최소 테스트 케이스 도출.
  - **AND 조건 (`A && B`)**: `(T, T)` 기준 ➔ **`(F, F)` 제외** (필수: (T,T), (T,F), (F,T))
  - **OR 조건 (`A || B`)**: `(F, F)` 기준 ➔ **`(T, T)` 제외** (필수: (F,F), (T,F), (F,T))
- **원인-결과 그래프 (Cause-Effect Graph)**:
  - 논리 기호: `∨ = OR`, `∧ = AND`, `~ = NOT`, `실선 = Identity(동치)`
  - 제약 표기법: Exclusive(E), Inclusive(I), One and only one(O), Requires(R) [원인 제약] vs Masks(M) [결과 제약].
- **신뢰성(Reliability) vs 가용성(Availability)**:
  - **신뢰성 (MTBF)**: 고장 없이 얼마나 연속으로 오래 버티는가?
  - **가용성 (Uptime Ratio)**: $	ext{가용성} = rac{	ext{MTBF}}{	ext{MTBF} + 	ext{MTTR(수리시간)}}$ ➔ 고장이 자주 나더라도 복구 속도(MTTR)가 극도로 빠르면 99.99% 고가용성 달성 가능.
- **Ian Sommerville 4대 신뢰성 정량 척도**:
  - **POFOD (Probability of Failure on Demand)**: 에어백, 소방 스프링클러, 원자로 비상 정지 등 평소 대기하다가 위기 신호(Demand)를 받았을 때 불발(오작동)될 확률 (안전 필수 시스템 척도).
  - **ROCOF**: 주기적 트랜잭션 시스템 (은행, 항공 예약)
  - **MTTF**: 장시간 지속 가동 시스템 (인공위성)
  - **MTBF**: 수리 가능한 일반 가용 시스템 (서버, DB)
- **ISO/IEC 25010 신뢰성(Reliability) 4대 하위 특성**:
  - 성숙성(Maturity), 가용성(Availability), 결함 허용성(Fault Tolerance - 리소스 부족 시에도 버팀), 회복성(Recoverability - 다운 후 데이터 복원).
- **Concolic Testing & TDD**:
  - Concolic: 구체적 실행(Concrete) + 기호 실행(Symbolic) 하이브리드 자동 테스트.
  - TDD 사이클: Red (실패 테스트) ➔ Green (최소 구현 통과) ➔ Refactor (리팩토링).

## 3. GoF 디자인 패턴 및 아키텍처 스타일

### 5개년 출제 현황

| 연도 | 2022 | 2023 | 2024 | 2025 | 2026 | 합계 | 출제 개년수 | 빈출도 |
|---|---|---|---|---|---|---|---|---|
| 문항수 | 1 | 1 | 1 | 1 | 1 | 5 | 5/5 | ★★★★★ |

### 핵심 포인트 요약
- **Command 패턴 + Adapter 패턴 복합 설계**:
  - **Command 패턴**: 요청자(`Button`)가 명령 인터페이스(`<<interface>> Command`)의 `execute()` 메서드를 호출하여 요청을 객체로 캡슐화.
  - **Adapter 패턴**: 어댑터(`Lamp`)가 표준 규격 인터페이스(`ILamp`)를 구현하면서, 내부에 기존 클래스(`LEDLight`)를 멤버변수로 소유하고 호출 방식을 중간에서 변환(위임)해 주는 돼지코 구조.
- **MVC 프레임워크 결합 GoF 패턴**:
  - Model ➔ View: **Observer 패턴** (상태 변경 통지)
  - View ➔ Controller: **Strategy 패턴** (행동/전략 주입)
  - View 계층 구조: **Composite 패턴**
  - *(오답 함정)*: Chain of Responsibility는 MVC 내부 결합 패턴이 아님.
- **아키텍처 스타일 POSA 1:1 킬러 키워드**:
  - 파이프-필터: **데이터 스트림 (Stream)**
  - 마이크로커널: **Core + 플러그 앤 플레이 (PnP)**
  - 리플렉션: **메타 객체 (Meta-object)**
  - 블랙보드: **공유 칠판 + 지식 소스 (전문가)**
  - 인터셉터: **이벤트 가로채기 (Intercept)**
- **SOLID 원칙 핵심**:
  - **DIP (의존 역전 원칙)**: 구체 클래스가 아니라 변화하기 어려운 인터페이스/추상클래스에 의존해야 함.
- **소프트웨어 제품라인 (Software Product Line, SPL)**:
  - 도메인 특화 핵심 자산(Core Assets)을 기반으로 다양한 고객 맞춤형 파생 완제품 패밀리를 양산하는 재사용 공학 기법.
