## 1. UML

### 5개년 출제 현황

| 연도 | 2022 | 2023 | 2024 | 2025 | 2026 | 합계 | 출제 개년수 | 빈출도 |
|---|---|---|---|---|---|---|---|---|
| 문항수 | 4 | 2 | 4 | 5 | 4 | 19 | 5/5 | ★★★★★ |

### 핵심 포인트 요약
- UML 4대 관계선의 코드-표기 매핑이 핵심 반복 출제 포인트: 실체화(Realization, `implements`, 점선+속이 빈 삼각형), 일반화(Generalization, `extends`, 실선+속이 빈 삼각형), 연관(Association, 멤버변수로 객체 소유, 실선 화살표), 의존(Dependency, 지역변수/파라미터로 일시적 사용, 점선 화살표).
- 시퀀스다이어그램의 조합조각(CombinedFragment): `break`는 가드조건이 참이면 내부 interaction만 실행하고 바깥 프레임을 즉시 탈출, 거짓이면 반대로 동작(내부를 건너뛰고 바깥을 계속 진행).
- State Machine의 진입/이탈 액션 실행 순서: 상태 진입 시 entry 액티비티 실행, 이탈 시 exit 액티비티 실행. 복합상태 간 전이에서는 "서브상태 exit → 이벤트 트리거 액션 → 슈퍼상태 exit → 전이 액션 → 타겟상태 entry" 순으로 진행.
- SysML은 UML의 일부 다이어그램(Use case, Sequence, State machine, Activity 등)을 재사용/차용함. Requirement Diagram의 관계 종류는 derive(파생)/satisfy(만족)/verify(검증)/refine(정제)/trace(추적)/copy(복사)이며, `include`는 UML 유스케이스 다이어그램 전용 관계로 SysML 요구사항 관계가 아님.
- 유스케이스 확장관계(`<<extend>>`): 조건부로 선택 실행되는 유스케이스를 표현하며, 확장 기능 유스케이스에서 확장 대상 유스케이스 방향으로 점선 화살표를 연결.
- 클래스 다이어그램에서 오버로딩(매개변수 개수/타입이 다른 동일 이름 메서드)·상속(부모-자식 관계)·오버라이딩(자식이 부모 메서드 재정의)을 동시에 식별하는 복합 문항 유형 반복.
- 순환복잡도(CC) = 분기(결정) 수 + 1, CBO(Coupling Between Objects) = 직접 결합된 클래스 개수 — 시퀀스 다이어그램에서 산출하는 계산형 문항.

### 연도별 출제 형식
- 2026: Java 코드 → UML 표기법 매칭형, 시퀀스다이어그램 조합조각(break) 실행흐름 추적형, 클래스다이어그램 → 객체지향 개념 묶음 판별형, State Machine 액션값 추적 계산형
- 2025: 시퀀스다이어그램 → 디자인패턴(Master-Slave) 판별형, Java 코드 → 클래스다이어그램 매칭형, SysML 요구사항 관계 보기선택형, State Machine 액션순서형, 유스케이스 확장관계형
- 2024: UML 다이어그램 유형(Activity Diagram) 판별형, SysML 다이어그램 특징 판별형, 리팩토링(Type Code 대체) 사례형, 요구사항 추출방법 판별형
- 2023: SysML-UML 공통 다이어그램 판별형, State Machine 복합상태 이탈 액션순서형
- 2022: Clean Architecture 계층 순서형, 디자인패턴 복합 판별형(Command+Adapter), 시퀀스-클래스다이어그램 다중성 오류 판별형, CC/CBO 계산형

### 오답 함정 / 헷갈리는 개념 구분
- `implements`(실체화, 점선+빈삼각형) vs `extends`(일반화, 실선+빈삼각형) — 표기법이 유사해 반복적으로 뒤바뀌어 출제됨.
- SysML Requirement Diagram 관계에 `include`는 없음 — UML 유스케이스 다이어그램 관계와 혼동 주의.
- `break` 프래그먼트는 조건 참/거짓에 따라 동작이 반대이므로, 문제에 구체적 값이 없을 때는 "가장 일반적인 경우(조건 거짓)"를 기준으로 풀이해야 함.

## 2. 테스트기법

### 5개년 출제 현황

| 연도 | 2022 | 2023 | 2024 | 2025 | 2026 | 합계 | 출제 개년수 | 빈출도 |
|---|---|---|---|---|---|---|---|---|
| 문항수 | 1 | 2 | 4 | 3 | 2 | 12 | 5/5 | ★★★★★ |

### 핵심 포인트 요약
- Concolic Testing(Concrete + Symbolic): 실제 입력값 기반 구체적 실행과 기호실행을 결합한 하이브리드 자동 테스트 기법. 수집된 경로 조건의 반대 조건을 제약조건 해결기(Solver)로 풀어 새 입력값을 생성하며 높은 분기 커버리지를 자동 달성(대표 도구: CREST, KLEE).
- TDD(테스트 주도 개발): Red(실패하는 테스트 작성) → Green(테스트를 통과하는 최소 구현) → Refactor(중복 제거·구조 개선)의 짧은 주기를 반복.
- 명세기반(블랙박스) 기법: 동등분할, 경계값분석, 결정테이블, 원인결과그래프, 조합테스트(Base Choice) — vs 구조기반(화이트박스) 기법: 조건/결정 커버리지, MC/DC(변형 조건/결정 커버리지).
- AI 테스트 4종 구분: 커버리지 테스트(입력 범위+기대 조건을 지정하고 그 범위 내 모든 입력이 조건을 만족하는지 확인) / 메타모픽 테스트(입력 변화와 결과의 관련성을 이용해 후속 케이스 도출) / 뉴런 커버리지 테스트(뉴런 활성화 정도 측정) / 적대적 공격(인위적 노이즈로 오작동 유도).
- Base Choice 조합테스트 케이스 수 = 1(base 케이스) + 각 인자별 (non-base 값 개수)의 합.
- MC/DC: AND 조건식(A && B)의 경우 조건별 독립성 검증 쌍(예: (T,T)vs(F,T), (T,T)vs(T,F))으로 최소 테스트 케이스 집합을 구성.

### 연도별 출제 형식
- 2026: Concolic Testing 개념 판별형, TDD 절차형
- 2025: 블랙박스(명세기반) 기법 오답찾기형, AI테스트기법(커버리지테스트) 판별형, 커버리지 충족 여부 판정형
- 2024: 애자일 방법론(XP/스크럼) 오답찾기형, 원인결과그래프 개념형, Base Choice 조합테스트 계산형, 변성테스팅(Metamorphic) 사례 판별형
- 2023: 결정테이블 커버리지 계산형, Release Testing 개념형
- 2022: MC/DC 커버리지 최소 테스트케이스 계산형

### 오답 함정 / 헷갈리는 개념 구분
- AI 테스트 4종(커버리지 테스트/메타모픽 테스트/뉴런 커버리지 테스트/적대적 공격) — 정의가 비슷해 보이지만 각각 "입력범위 검증", "입력-결과 관련성", "뉴런 활성화", "노이즈 유도"로 명확히 구분해야 함.
- 명세기반(블랙박스, 요구사항 기준) vs 구조기반(화이트박스, 소스코드 내부 논리 기준) — "조건/결정 커버리지는 명세기반이다"는 틀린 서술.

## 3. 디자인패턴

### 5개년 출제 현황

| 연도 | 2022 | 2023 | 2024 | 2025 | 2026 | 합계 | 출제 개년수 | 빈출도 |
|---|---|---|---|---|---|---|---|---|
| 문항수 | 1 | 1 | 1 | 1 | 1 | 5 | 5/5 | ★★★★★ |

### 핵심 포인트 요약
- MVC 프레임워크 내부에 결합된 GoF 패턴: Model→View는 Observer 패턴(상태 변경 통지), View→Controller는 Strategy 패턴(행동 전략 제공), View 계층 구성은 Composite 패턴 — Chain of Responsibility는 MVC에서 일반적으로 사용되는 패턴이 아님.
- Master-Slave(Master-Worker) 패턴: Master가 다수의 Slave에게 작업을 분배하고 결과를 취합해 반환하는 병렬/분산 처리 구조.
- SOLID 원칙 중 DIP(의존 역전 원칙): 변화하기 쉬운 구체 클래스보다 변화하기 어려운 추상클래스/인터페이스에 의존해야 함.
- Chain of Responsibility 패턴: 요청 처리 핸들러들을 연쇄적으로 연결해 다음 객체로 요청을 전달하는 구조(시퀀스 다이어그램에서 판별하는 문항으로 출제).
- Command 패턴(요청을 캡슐화해 execute()로 실행) + Adapter 패턴(기존 인터페이스를 다른 인터페이스로 위임/변환)이 한 문항에서 동시에 출제되는 복합 사례 존재.

### 연도별 출제 형식
- 2026: MVC 내부 결합 패턴 오답찾기형
- 2025: 시퀀스다이어그램 → 디자인패턴(Master-Slave) 판별형
- 2024: SOLID 원칙(DIP) 판별형
- 2023: 시퀀스다이어그램 → 디자인패턴(Chain of Responsibility) 판별형
- 2022: 클래스다이어그램 → 복합 패턴 판별형(Command + Adapter)

### 오답 함정 / 헷갈리는 개념 구분
- Chain of Responsibility는 MVC 구조에서 일반적으로 사용되는 패턴이 "아님" — MVC 내부 3대 패턴(Observer/Strategy/Composite)과 혼동하지 않도록 주의.
- DIP를 다른 SOLID 원칙(SRP/OCP/LSP/ISP)과 혼동하지 않도록, "추상화에 의존 vs 구체화에 의존"이라는 키워드로 구분.
