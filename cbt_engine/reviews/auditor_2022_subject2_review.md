### 🔹 Q3. 리팩토링 기법 소스코드 판별 (변수 캡슐화하기 Encapsulate Variable)

**[문제 요약]**
> (변경전) `let defaultOwner = {firstName: "Martin", lastName: "Fowler"};`  
> (변경후) `let defaultOwnerData = ...; export function defaultOwner() { return defaultOwnerData; } export function setDefaultOwner(arg) { defaultOwnerData = arg; }`  
> ➔ **정답: ②번 (Encapsulate Variable)**

**[대화 내용]**
> **사용자**: "여기 function 앞에 export 라는게 public이라는 의미인거 같은데"
>
> **[임선우]**: "정확하게 핵심을 짚으셨습니다! JavaScript(ES6 모듈) 문법으로, `let defaultOwnerData`는 export가 없어 모듈 내부에서만 쓰이는 `private` 변수가 되고, `export function ...`은 외부에서 호출할 수 있는 `public` 게터/세터 메서드가 됩니다. Java의 private 필드 + public Getter/Setter 캡슐화와 완벽히 1:1로 대응됩니다."
>
> **사용자**: "JS에서는 export라고 명시적으로 작성할 때만 public이고 안적으면 자동으로 private이 되는 모양이네. 그럼 private을 명시적으로 선언할 수는 없나"
>
> **[임선우]**: "파일(모듈) 레벨에서는 export 유무로 결정되고, 클래스 내부에서는 최신 JS 표준인 `#변수명` (해시 기호)을 붙이거나 TypeScript의 `private` 키워드를 사용하여 명시적 private을 선언합니다."

**[문제 요약]**

**[대화 내용]**

>
> **사용자**: "아.. 조건문이 없을 때도 복잡도는 1이다. 즉, 복잡도의 최소값은 1이다"
>
> **[임선우]**: "완벽합니다! 단위 테스트 관점에서도 코드를 최소 1번은 실행해 봐야 하므로 최소 복잡도가 1이 됩니다."

### 🔹 Q5. Java 이진 탐색(Binary Search) 소스코드 실행 결과 추적

**[문제 요약]**
> 숫자 배열 `{1, 2, 3, 4}`와 `k = 3`이 입력되었을 때 Java 이진 탐색 알고리즘 `search(list, 3)`의 출력 결과는?  
> ➔ **정답: ②번 (2)**

**[대화 내용]**
> **사용자**: "1회전만 자세히 봅시다. left는 0, right는 리스트의 사이즈-1이니까 리스트의 사이즈는 4, 따라서 right는 3"
>
> **[임선우]**: "네! 1회전에서 `mid = 0 + (3-0)/2 = 1` ➔ `list.get(1) = 2 < 3`이므로 `left = mid + 1 = 2`가 됩니다. 2회전에서 `mid = 2 + (3-2)/2 = 2` ➔ `list.get(2) = 3 == 3` 일치하여 `result = 2`가 저장되고 루프가 종료되어 최종 2가 출력됩니다."
>
> **사용자**: "이거는 코드를 하나하나 따라가면 알 수는 있을 거 같은데 시간이 너무 오래 걸리는걸"
>
> **[임선우]**: "그래서 시험장에서는 5초 컷 직관 스킬로 풉니다! 코드 구조를 보고 '이진 탐색'임을 식별한 뒤, 이진 탐색은 값이 아니라 **인덱스(위치)**를 반환하므로 배열 `{1, 2, 3, 4}`에서 값 3이 있는 인덱스는 **`2`**번(0번=1, 1번=2, 2번=3)임을 3초 만에 찾고 ②번을 찍으면 됩니다."

### 🔹 Q22. 시스템 확실성(Dependability) 속성 (가용성 Availability vs 복원성 Resilience)

**[문제 요약]**
> (가) 주어진 시점에 시스템이 작동하여 서비스를 제공할 확률 ➔ 가용성(Availability)  
> (나) 고장이나 사이버 공격 시 중요 서비스를 유지하는 능력 ➔ 복원성(Resilience)  
> ➔ **정답: ②번 (가용성, 복원성)**

**[대화 내용]**
> **사용자**: "그런데 신뢰성이 확보되면 가용성도 자연스럽게 확보되는거 아닌가. 용어에서 오는 느낌은 비슷한데 수학적으로는 차이가 있네"
>
> **[임선우]**: "정확합니다! 수학적으로 $\text{가용성} = \frac{\text{MTBF}}{\text{MTBF} + \text{MTTR(수리시간)}}$ 입니다. 1시간에 1번씩 뻗어도(신뢰성 바닥), 0.1초 만에 자동 페일오버 복구되면(MTTR 극소) 가용성은 99.99%가 나옵니다. 현대 클라우드 HA 아키텍처의 핵심입니다."

### 🔹 Q25. 시퀀스 다이어그램 기반 순환복잡도(CC) 및 클래스 결합도(CBO) 산출

**[문제 요약]**
> Class1이 loop, break, opt 프래그먼트 내에서 Class2의 객체(O21, O22)와 Class3의 객체를 호출할 때 Class1의 CC와 CBO는?  
> ➔ **정답: ④번 (CC = 4, CBO = 2)**

**[대화 내용]**
> **[임선우]**: 
> 1. **순환복잡도 (CC)**: 분기 프래그먼트 3개(loop, break, opt) + 기본 경로 1 = **`CC = 4`**
> 2. **클래스 결합도 (CBO)**: 객체는 O21, Class3, O22로 3개이지만, CBO는 결합된 **'클래스 종류 수'**를 세므로 `Class2`와 `Class3` 총 2개 = **`CBO = 2`**
>
> **사용자**: "이 과목은 다이어그램이 문제네"
>
> **[임선우]**: "2022년 25문항 중 무려 35% 이상이 다이어그램 판독 문제였습니다. 하지만 오늘 다이어그램 4대 판독 공식(다중성, 복잡도 프래그먼트, 상속/위임 관계, 원인결과 게이트)을 완벽하게 정리하셨습니다!"
