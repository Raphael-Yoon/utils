| :---: | :--- | :---: | :--- |
| **Q1** | 클린 아키텍처 & SDP | **①** | • 로버트 C. 마틴의 의존성 규칙: 바깥쪽(세부기술) ➔ 안쪽(핵심업무) 단방향 의존 ($P4 \rightarrow P3 \rightarrow P2 \rightarrow P1$)<br>• 불안정성 지표 $I = C_e / (C_a + C_e)$: 들어오고 나가는 선 중 '나가는 선'의 비율 ($I=0$ 최대안정 엔티티로 의존이 흘러야 함)<br>• SOLID(클래스 단위)를 시스템/패키지 전체로 확장한 것이 클린 아키텍처 |
| **Q2** | ISO 25010 유지보수성 | **①** | • 유지보수성 5대 부특성 [모·재·분·수·시]: 모듈성, 재사용성, 분석성, 수정성, 시험성<br>• 가용성(신뢰성 소속), 정확성(기능적합성 소속), 학습성(사용성 소속) 1초 구분<br>• 주관식 암기가 아닌 맥락 인지(Recognition) 기반 매칭 전략 |
| **Q3** | 블랙박스 vs 화이트박스 | **③** | • 소스코드 열람 여부 기준: 명세서/입출력(블랙박스) vs 소스코드 제어흐름(화이트박스)<br>• 전표 승인 10만원 실무 예시: 화면 99,999원/100,001원 입력(경계값) vs `ApprovalService.java` if문 분기 커버리지 검증<br>• 조건/결정 커버리지(화이트박스) vs 결정 테이블(블랙박스)의 MECE 조건 검증 비교 |
| **Q4** | Master-Slave 패턴 | **①** | • `:Main`(Master)이 대용량 데이터를 `split`하여 2개의 `:Controller`(Slave)에 `par`(병렬) 분배 후 `merge` 취합<br>• Master-Slave(양방향 일감분배+결과취합) vs Observer(단방향 1:N 상태통지) 결정적 차이<br>• 멀티코어/멀티프로세서(SMP/NUMA) 하드웨어 병렬 연산 및 OS 동시성 vs 병렬성 비교 |
| **Q5** | UML 클래스 표기법 | **②** | • 이탤릭체(*Class1*) = 추상클래스, 실선+속이 빈 삼각형(△) = 일반화(extends 상속)<br>• `{readOnly}` = Java `final`, 밑줄 속성(`<u>attr2</u>`) = Java `static` 정적 변수<br>• 추상클래스/인터페이스의 본질: 필수 기능 구현을 강제하는 '구현의 계약(Contract)' |
| **Q6** | ISO 25023 신뢰성 메트릭 | **③** | • 신뢰성 3대 지표: MTBF(평균고장간격), MTTR(평균수리시간), 가용성($\frac{\text{MTBF}}{\text{MTBF}+\text{MTTR}}$)<br>• 결함 발견율(Defect Detection Rate)은 운영 신뢰성 지표가 아닌 '테스트 공정 관리 지표' |
| **Q7** | SysML 요구사항 다이어그램 | **①** | • SysML: UML 2.0에 HW, 인력, 물리/수학 수식(파라메트릭), 요구사항 추적을 결합한 확장 언어<br>• 요구사항 3대 관계: `<<derive>>`(파생), `<<satisfy>>`(부품이 요구사항 만족), `<<verify>>`(시험 검증)<br>• `<<include>>`는 UML 유스케이스 관계이므로 제외 |
| **Q8** | AI 테스팅 4대 기법 | **②** | • 커버리지 테스트: 지정된 입력 범위 내 모든 데이터가 기대 안전 조건을 충족하는지 검증 (Q8 정답)<br>• 메타모픽(입력 변형 시 관계 불변성 검증), 뉴런 커버리지(신경망 은닉층 뉴런 점등률 자동 측정), 적대적 공격(미세 노이즈 주입 오분류 유도) |
| **Q9** | AI 데이터 거리 측도 | **①** | • 유클리드 거리 ($L_2$): 두 점을 잇는 최단 대각선 직선 거리 ('가' - 피타고라스 빗변)<br>• 맨해튼 거리 ($L_1$): 가로 + 세로 이동거리의 합 ('나 + 다')<br>• 체비쇼프 거리 ($L_\infty$): 가로/세로 편차 중 '더 긴 축 하나(최댓값)'의 길이 (체스의 킹 이동 횟수) |
| **Q10** | 오픈소스 LGPL 라이선스 | **③** | • LGPL 2대 시그니처 조항: '라이브러리(Library)' 수정분 공개(라) & 독점 응용프로그램 소스 비공개 및 리링크 허용(사)<br>• 전염성 비교: GPL(전체 공개), LGPL(라이브러리만 공개), MPL(수정 파일만 공개), BSD/MIT(완전 비공개)<br>• 특급 감사 팁: 사내 내부 시스템 구축 시(외부 미배포)에는 GPL도 공개 의무 0%! |
| **Q11** | 컨테이너 vs 가상머신 | **④** | • 컨테이너(Docker): 호스트 OS 커널 1개 공유, 하이퍼바이저 불필요, 1초 기동, MSA 최적화 (나, 다)<br>• 가상머신(VM): 하이퍼바이저 기반 독립 Guest OS, 이기종 OS 동시 구동 가능(Windows WAS + Linux DB) (가, 라, 마, 바)<br>• WSL2의 본질: 윈도우 Hyper-V 하이퍼바이저 위에서 리눅스 커널을 띄우는 초경량 가상머신(VM) 기술 |
| **Q12** | MSA 설계 4단계 절차 | **③** | • 순서: 목표 식별(다) ➔ 원칙/정책 수립(나) ➔ 핵심 아키텍처 스케치(가) ➔ 현황 진단 및 영향분석(라)<br>• 1초 컷 스킬: 모든 공학 설계의 출발점은 '목표 식별(다)'이므로 (다)로 시작하는 ③번 즉시 확정 |

## 4. 결론 및 성과
* **성과**: 2025년 제2과목 소프트웨어공학 25문항에 대한 CBT 원천 데이터(JSON)가 10년 차 IT 감사 실무 경험과 최신 수험 트렌드를 완벽히 반영한 최고 품질의 심층 해설로 고도화되었습니다.
* **가이드 보완**: 전사 지침(AGENTS.md) 내 CBT 종료 시 'JSON 해설 업데이트'와 '대화 리뷰 보고서(MD) 동시 생성'을 공식 절차로 명문화 완료.
* **향후 계획**: 차기 과목(데이터베이스, 시스템구조, 보안 등) 진행 시에도 동일한 콤팩트 렌더링, 실무 비유, 표준 리뷰 템플릿을 엄격히 적용합니다.
