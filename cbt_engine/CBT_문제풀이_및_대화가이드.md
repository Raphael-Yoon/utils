# 🌸 풀어봄(Pool-eobom) CBT 시스템 문제풀이 및 대화 렌더링 가이드라인

본 문서는 풀어봄(Pool-eobom) CBT 시스템 문제 검토, 기출문제 풀이 대화, 해설 제공 및 사후 지식 자산화(JSON/리뷰 리포트)를 총괄하는 공식 단일 업무 가이드라인(SOP)입니다.

---

## 📌 1. 전담 코치 및 원천 데이터 참조 기준

1. **전담 코치**:
   - 기출문제 풀이 및 해설 대화는 개발4팀의 수험 전담 코치 **`[임선우]`**가 주도하며, 법령/ITGC 심층 쟁점 발생 시 IT 감사팀과 협력합니다.
2. **원천 데이터 기준**:
   - 시험 리뷰 및 문제 풀이 시 웹 검색이나 외부 임의 데이터가 아닌, 반드시 `utils/cbt_engine/exams/` 폴더 내에 등록되어 있는 표준 JSON 파일(예: `auditor_YYYY_subjectX.json`, `auditor_YYYY.json` 등)을 직접 조회하여 문항, 보기, 정답, 공식 해설의 기준으로 삼습니다.
   - 시험별 반복 출제 핵심개념은 `utils/cbt_engine/reviews/concept_cards/{시험키}_subjectN_핵심개념카드.md` 형식으로 정리되어 있으므로(시험키는 `exams/` JSON 파일명 접두어와 동일 — 예: `auditor`, 추후 `bigdata`/`digital_forensic`/`sqld` 등), 문제풀이 진행 전 해당 시험·과목 카드를 먼저 조회하여 참고 기준으로 삼습니다.
   - 정보시스템감리사(`auditor_subject1~5_핵심개념카드.md`, 2022-2026 5개년 기준)는 이미 21개 핵심개념이 정리되어 있으며, 다른 시험은 카드가 아직 없으면 새로 만들 때도 이 파일명 규칙을 그대로 따릅니다.

---

## 📌 2. 문제풀이 진행 원칙 (Step-by-Step Question Control)

1. **5개년 출제 팩트 및 중요도 정밀 표기**:
   - 문제를 제시할 때 상단에 해당 토픽/세부 유형의 **최근 5개년(2022-2026년) 실제 출제 연도와 빈도, 중요도**를 정확한 데이터베이스 팩트 기반으로 명시합니다. (대분류로 포괄 퉁치기 금지)
   - 정보시스템감리사 문항은 해당 과목의 `핵심개념카드`에 이 문항이 속하는 개념이 있는지 먼저 확인하고, 있다면 그 카드의 "5개년 출제 현황"·"핵심 포인트"·"오답 함정"을 인용해 일관된 트렌드/중요도 판단을 유지합니다. 카드에 아직 없는 새로운 관점(계산법, 실무 비유, 오답 함정 등)이 대화 중 도출되면 4번 항목(마무리 SOP)에 따라 카드에도 반영합니다.
   - **연계 설명 출처 명시(필수)**: 이번 문항이 개념의 일부(A)만 물어봤어도, 같은 개념에 속한 카드 상의 다른 핵심 포인트(B, C 등)를 함께 짚어줄 수 있습니다. 이때는 반드시 `📇 [핵심개념카드 연계 — {과목}/{개념명}]` 같은 명시적 표시를 붙여, 이 설명이 카드 참조에 의한 것임을 구분되게 밝힙니다. 표시 없이 덧붙이는 설명과 섞이면 사용자가 "왜 이 얘기가 나왔는지" 알 수 없으므로, 카드 기반 확장 설명은 항상 이 표기를 통해서만 제공합니다.
2. **임의 진행 절대 금지 (명시적 '다음' 트리거 필수)**:
   - 사용자가 명시적으로 `"다음"`, `"넘어가자"`, `"다음 문제 보자"` 등으로 지시하기 전에는 **어떠한 경우에도 절대로 다음 문제를 먼저 제시하거나 앞서 나가지 않습니다.**
   - 사용자의 질문이나 피드백에는 질문에 대한 답변만 충실히 제공한 후, 반드시 온전히 대기 상태로 응답을 끝맺습니다.
3. **즉시 정답 및 핵심 중심 해설 제공**:
   - 사용자는 이미 사전에 CBT 엔진을 통해 문제를 풀고 채점까지 마친 상태입니다.
   - 따라서 *"몇 번으로 생각하시나요?"* 등의 정답을 되묻는 질문을 하지 않고, **문제 제시와 동시에 정답 번호, 핵심 계산/판단 근거, 지문별 핵심 이유를 군더더기 없이 간결·명료하게 제공**합니다.
4. **현재 문항 심층 완결**:
   - 현재 문항의 출제 배경, 핵심 판별 쟁점, 실무적 비유에 대한 논의와 질의응답이 완전히 마무리될 때까지 현재 문항에만 100% 집중합니다.

## 📌 3. 대화창 마크다운 서식 및 가독성 규칙 (Markdown Formatting)

1. **간결한 콤팩트 레이아웃**:
   - 핵심 공식, 근거 법령/기준 1줄, 오답 포인트 1줄 요약 위주로 가독성을 극대화합니다.
2. **`mermaid` 코드 블록 사용 금지**:
   - IDE 대화창 렌더러가 머메이드 그래픽 렌더링을 지원하지 않아 raw 텍스트 박스로 노출되므로 일체 사용하지 않습니다.
   - 다이어그램이 필요한 경우 **마크다운 표(Table)**나 화살표 기호(`➔`, `➜`) 기반 텍스트 구조도를 사용합니다.
3. **물결표(`~`) 취소선 방지**:
   - 마크다운 파서가 물결표를 취소선(`~~...~~`)으로 오인하여 문장 전체에 취소선이 그어지는 현상을 방지합니다.
   - 숫자나 범위 표기 시 반드시 **역슬래시 이스케이프(`\~`)**, **공백 추가(`1 ~ 2개`)**, 또는 **하이픈(`1-2개`)**을 사용합니다.

## 📌 4. 문제 데이터(JSON) 해설 보강 및 리뷰 리포트 생성 SOP (Finalize & Persist)

1. **트리거 조건 (명시적 마무리 지시)**:
   - 사용자가 `"이거 마무리하자"`, `"마무리 하구요"`, `"정리하고 넘어가자"`, `"JSON에 반영해줘"` 등으로 문항 또는 과목 마무리 의사를 밝힐 때 즉시 실행합니다.
2. **반영 내용 및 절차**:
   - **① 과목 대화 리뷰 마크다운(MD) 리포트 생성**:
     - 과목 리뷰가 완료되면 전체 대화의 핵심 논점, 25개 문항별 심층 인사이트, 직관적 실무 비유, 출제자 함정 분석을 총망라한 **리뷰 보고서(`utils/cbt_engine/reviews/auditor_YYYY_subjectX_review.md`)**를 `reviews/` 전용 폴더에 작성하여 영구 보존합니다.
   - **② JSON 해설 영구 업데이트**:
     - 대화 중 논의된 핵심 쟁점, 질의응답(Q&A), 실무 비유, 직관적 공식, 정밀 팩트를 해당 시험 JSON 파일(`utils/cbt_engine/exams/auditor_YYYY_subjectX.json`)의 각 문항 `explanation` 필드 하단에 `\n\n💡 [실무 쟁점 & 핵심 Q&A 노트]\n...` 형식으로 반영(저장)합니다.
   - **③ 핵심개념카드 동기화**:
     - 마무리된 문항이 해당 시험의 `핵심개념카드`(`reviews/concept_cards/{시험키}_subjectN_핵심개념카드.md`)에 이미 있는 개념에 속하면, 대화 중 새로 도출된 핵심 포인트·오답 함정·연도별 출제 형식을 반영해 최신화합니다.
     - 기존 카드의 개념 어디에도 속하지 않는 새로운 반복 토픽이 발견되면, 카드에 신규 개념 항목을 추가할지 매니저에게 확인 후 반영합니다.
     - 아직 해당 시험의 핵심개념카드 자체가 없는 경우(감리사 외 시험), 신규 파일을 `{시험키}_subjectN_핵심개념카드.md` 규칙으로 생성할지 매니저에게 확인 후 진행합니다.
3. **완료 보고**:
   - `reviews/` 폴더 내 리뷰 MD 보고서 생성, JSON 파일 수정, 핵심개념카드 동기화가 완료되었음을 1줄로 명확히 보고한 후 다음 지시를 대기합니다.

## 📌 5. 시험 직전 핵심 요약본(파이널 체크시트) 제작 가이드라인 (Final Cram & Trap Sheet SOP)

1. **목적 및 시험 단위 통합 원칙 (One-Exam One-Handbook Rule)**:
   - 문제를 새로 생성하거나 풀이하는 것이 아니라, **고사장 입실 후 스마트폰 제출 전 대기시간 10~20분 동안 한 손으로 스크롤하며 빠르게 완독할 수 있는 모바일 최적화 초압축 요약본**을 구축합니다.
   - **시험 단위 단일 통합 원칙**: 과목별로 파일을 쪼개지 않고, **해당 시험의 전 과목(1~N과목)을 단 한 권의 초밀도 요약본(`{시험키}_직전요약본.md`)으로 통합**합니다. 수험생이 스마트폰에서 단 하나의 문서만 열어 아래로 쭉 내리며 10분 만에 전 과목 점검을 끝낼 수 있도록 합니다.
   - **분량 (초압축 A4 2~3장 내외)**: 장황한 설명이나 사족은 전면 배제하며, **시험 전체를 통틀어 A4 2~3장 내외(스마트폰 10~15분 완독 분량)**로 극도로 압축합니다. 과목당 가장 치명적인 킬러 함정과 빈출 1초 판별 키워드 5~7개씩만 엄선합니다.

2. **저장 위치 및 파일명 명명 규칙 (File Path & Naming)**:
   - **경로**: `utils/cbt_engine/reviews/cram_sheets/{시험키}_직전요약본.md`
   - *(적용 예시)*:
     - `auditor_직전요약본.md` (정보시스템감리사 제1~5과목 전체 통합본, 10분 완독용)
     - `bigdata_직전요약본.md` (빅데이터분석기사 제1~4과목 전체 통합본, 10분 완독용)
     - `sqld_직전요약본.md` (SQL 개발자 제1~2과목 전체 통합본, 5분 완독용)
     - `digital_forensic_직전요약본.md` (디지털포렌식전문가 제1~5과목 전체 통합본, 10분 완독용)

3. **요약본 모바일 콤팩트 구성 체계 (Mobile-First Layout)**:
   - **서론·안내문 절대 금지**: 이미 요약본 버튼을 눌러 들어온 사용자이므로 `'이 문서는 요약본입니다'`, `'고사장 완독 가이드'`, `'시간 배분/합격 기준'` 등 메타 안내문이나 사족은 단 한 줄도 작성하지 않습니다. **문서 첫 줄부터 즉시 `## 📌 [1과목] ...` 핵심 내용으로 시작**합니다.
   - 줄글 설명은 일체 배제하고, **[키워드 ➔ 정답]**, **[오답 함정 ➔ 1초 거르기]** 중심의 직관적 불릿 표기:
     - **① [과목별 1초 판별 키워드]**: 시험장에 바로 써먹는 필수 공식, 기한 수치, 개념 매칭.
     - **② [자주 낚이는 단골 함정 지문 (Trap Buster)]**: 실제 오답률 높은 매력적 오답 지문과 파훼법.
     - **③ [헷갈리는 2지선다 1:1 대조]**: 시험장에서 둘 중 하나 고민하게 만드는 쌍둥이 개념 차이점.

4. **원천 데이터 추출 기준 (Data Source)**:
   - `exams/*.json`의 기출 해설, `concept_cards/*.md`의 빈출 팩트, `reviews/*.md` 실시간 대화록에서 도출된 핵심 인사이트 중 **'직전에 안 보면 실수로 틀리기 쉬운 것'**만 정밀 필터링하여 수록합니다.

5. **공식 트리거 명령어 및 자동 실행 규칙 (Trigger & Execution)**:
   - 사용자가 **`"{시험명} 핵심요약본 생성하자"`**, **`"{시험명} 직전요약본 만들어줘"`**, **`"{시험명} 치트시트 뽑아줘"`** 등으로 요청하면 즉시 착수합니다.
     - *(예: `"감리사 핵심요약본 생성하자"`, `"SQLD 직전요약본 만들어줘"`, `"포렌식 치트시트 뽑아줘"` 등)*
   - 에이전트는 해당 시험의 기출 데이터셋(`exams/`) 및 개념카드(`concept_cards/`)를 통합 분석하여 전 과목을 단일 문서(`utils/cbt_engine/reviews/cram_sheets/{시험키}_직전요약본.md`)로 10분 완독 스펙에 맞춰 즉시 생성하고 클릭 가능한 링크로 완료 보고합니다.
